# v0.9.2-beta Reliability

## Summary
v0.9.2-beta is a broad reliability release focused on fleet provisioning, paired input-control determinism, remote OTA pacing, PowerSave behavior, Flasher bulk operations, and clearer fleet visibility. It builds on v0.9.1-beta by making the gateway peer cache more authoritative, reducing LoRa collisions during maintenance and OTA, and tightening the Flasher operator workflows used for provisioning, settings, monitoring, and remote updates.

## Highlights
- Paired input-control is now deterministic across fleets: the gateway sends one actuating group command, waits for ACKs, and then uses non-actuating `PollRequest` confirmations for any missing nodes instead of sending late targeted `Change` packets that could shift relay timing.
- Remote OTA is now paced and stateful end to end: Flasher queue rows stay visible until terminal states, firmware silences LoRa telemetry throughout the OTA pull, gateway-mediated control frames are paced over multiple ticks, and duplicate OTA triggers are rejected while a pull is active.
- Fleet provisioning now treats chip ID as the physical identity, preserves persisted chip/address pairings, merges gateway target lists by default, and prevents re-provisioning/factory-reset cycles from exhausting or collapsing addresses.
- PowerSave was simplified into a binary Full Power / PowerSave model, with an optional `power_save_listen_only` mode for ultra-lean remote operation.
- Flasher fleet, monitor, settings, and bulk flash workflows are more stable: port ownership is separated by tab, serial jobs are queued per port, queued OTA rows stay visible, and device rows show clearer relay, sensor, WiFi, firmware, and uptime state.
- Release/build hygiene is stronger: dev build revisions are operator-visible, flasher manifests auto-sync from `VERSION`, native helper tests are part of the release gate, and release automation now prunes old GitHub Actions workflow runs.

## Firmware Changes
- Reworked paired input-control group confirmation:
  - Broadcast `Change` remains the only actuating command for the relay transition.
  - Missing ACK recovery now uses correlated `PollRequest`/`PollResponse` checks.
  - `PollRequest` flag `0x04` marks a group correlation poll and echoes the command ID without feeding that value into time sync.
  - Heartbeat sync now uses the same multi-target group path as input changes.
- Improved ACK and peer-cache truth:
  - Relay state updates from valid matching ACK packets and real remote status packets.
  - Dry-contact input state is no longer inferred from ACK packets.
  - Fleet Open/Closed state is only marked known from real remote status or sensor telemetry.
  - Receivers accept same-key gateway input-control packets from LoRa address `254`, helping recovered remotes respond even when pairing metadata is stale.
- Hardened provisioning and fleet identity:
  - Persisted address-to-chip ID pairings survive gateway reboot and Flasher reconnection.
  - Gateway target lists merge by default rather than replacing the whole fleet list.
  - Re-provisioning factory-reset devices reclaims addresses by chip ID and avoids address exhaustion.
  - Config loading no longer rewrites multi-target gateway lists from the legacy single `remote_address`.
  - Receiver provisioning disables incompatible paired-input gateway control instead of resetting the receiver address.
- Improved maintenance and telemetry:
  - Remote uptime now travels on the normal maintenance version page.
  - Sensor telemetry reporting restores DS18B20 temperature and 4-20 mA tank data.
  - Maintenance inventory includes compact identity/status details such as chip ID, firmware version, WiFi state/IP, MQTT state, uptime, and freshness.
  - MaintenanceRequest replies are destination-checked to avoid scan collisions.
- Improved OTA behavior:
  - Firmware suppresses LoRa maintenance chatter during OTA pulls.
  - Gateway-mediated OTA sends SHA256 before remote HTTP download.
  - OTA verifies the same HTTP stream it flashes.
  - Control frames are paced over multiple ticks instead of burst in one serial-admin call.
  - Gateway reports `gateway_busy` when another OTA trigger is already active.
- Reduced memory and runtime risk:
  - Several transient heap-string helpers were removed from WiFi, hostname, DS18B20, MQTT, settings, and serial-admin paths.
  - Fixed settings strings now use inline buffers instead of long-lived heap-backed `String` fields.
  - Version packet fields use build-generated numeric macros rather than runtime parsing.
- PowerSave changes:
  - PowerSave is now a binary Full Power / PowerSave state model.
  - `power_save_listen_only` adds a lean remote mode that disables WiFi, background sensor polling, MQTT, status LEDs, and Serial Admin.
  - Serial activity and pending PowerSave state handling were tightened to avoid accidental wake/sleep stickiness.

## Flasher Changes
- Provisioning and gateway handling:
  - Provision uses the connected gateway as the fleet-key authority and blocks accidental commissioned-gateway re-keying.
  - Gateway port loading is more reliable, including startup retry and race prevention.
  - Gateway flash can proceed while another serial port is flashing.
  - EasyPair preserves gateway target lists and reserves known addresses.
  - Dense factory scans use wider reply timing to reduce missed remotes.
- Fleet and Monitor:
  - Fleet now treats the gateway peer cache as the primary view.
  - Fleet and Monitor preserve cached rows across tab changes and rate-limit explicit scans.
  - Fleet shows remote relay state as On, Off, or waiting.
  - Sensors display falls back to normal dry-contact input state when debug-only feedback is absent.
  - Uptime, reboot, OTA, MQTT, relay, sensor, WiFi, and IP presentation were clarified.
  - MQTT is shown only when explicitly enabled; otherwise rows show `-`.
- OTA and upgrade UX:
  - Multi-device OTA queueing is more robust and visible.
  - Active OTA rows remain queued/active until terminal status is observed.
  - Remote rows matching the target firmware version are treated as successful updates.
  - OTA retry, reboot tracking, subnet filtering, and local status history were tightened to prevent stale or misleading UI transitions.
  - The gateway upgrade dialog now shows current and target firmware versions.
- Settings and actions:
  - WiFi, sensors, and fleet key operations were consolidated into a tabbed device settings modal.
  - The settings pane includes a sticky save/reboot footer.
  - Fleet Key viewing/editing and remote Fleet Key changes are guarded with explicit warnings.
  - Settings can copy fetched config JSON for field recovery.
  - Secret-preserving saves and cache clearing after reboot/reset/flash/provisioning are clearer.
- Bulk flashing and serial behavior:
  - USB ports are tracked independently for Flash, Provision, Fleet, Monitor, and Settings.
  - Serial jobs are queued per port.
  - Bulk flash progress is weighted across erase/write/verify phases and parses decimal esptool percentages.
  - Unplugged devices are removed from bulk operation status.
  - Completed flash/reset state is cleared when a port is recycled.
  - Local packaged installs continue release fetching even when `.pio/build/lrs_za/firmware.bin` is missing.
- Operator polish:
  - Fleet table labels were tightened (`LoRa` to `Addr`, WiFi `Connected` to `OK`).
  - IP column hides when no active remote reports an IP.
  - Dry-contact words are colorized for faster scanning.
  - UDP logs auto-follow the latest line and include copy plus expand/collapse controls.
  - The Monitor page clearly carries the beta label.

## MQTT And Protocol Changes
- Peer topics were expanded and cleaned:
  - LWT availability topics.
  - `peers/` naming.
  - Decimal addressing.
  - Compound paths with chip ID and zero-padded address.
  - Peer publish cache sized to `LRS_MAX_PEERS`.
  - Operational peer topics blank on timeout and include `last_seen_age_s`.
- Protocol documentation now describes:
  - Non-actuating `PollRequest` confirmation for missing group ACKs.
  - Correlated group poll flag `0x04`.
  - Destination-checked maintenance responses.
  - OTA SHA256 and pacing behavior.

## Build, Test, And Release Tooling
- Dev builds now use visible revisions such as `0.9.2~122`.
- Flasher package manifests and lockfiles sync from root `VERSION`.
- Versioned firmware binaries are produced as `lrs-firmware-<version>.bin`.
- Native PlatformIO tests cover pure helper code for fixed settings strings and mode/role parsing.
- Python metadata tests cover build-version parsing.
- Release validation now requires:
  - `pio test -e native`
  - `python3 tools/test_version_metadata.py`
  - `pio run -e lrs_za`
  - `pio run -e lrs_us`
- Release automation now prunes old `package_flasher.yml` workflow runs, keeping the latest 10 by default.

## Removed
- Device-hosted operator UI/admin services remain removed from normal firmware.
- Stale device-admin helper scripts and old Web UI extraction/local DevMon helpers have been removed.
- Dormant onboard automation-rule runtime code remains removed until it returns with a supported Flasher/serial-admin management surface.
- Pseudo-`mesh` aliases and unsupported settings audit fields have been removed.
